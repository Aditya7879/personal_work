1 / High level · System context

Who and what the console connects to

Three roles use one console. Around it: the NEO Companion API for answer generation, the L’Oréal AI Gateway (Claude Sonnet 4.6) for judging, Neo4j for source passages, and BigQuery as the system of record.

—

Rendering the system context…

Two separate AI connections. NEO generates the answer; the gateway judges it. They have independent authorization — being allowed to invoke NEO does not authorize gateway calls, or vice versa.

2 / High level · Cloud deployment

Two Cloud Run services behind Google identity

The browser signs in through IAP to the frontend service; the frontend calls the backend with a workload identity token. Deploys are scripted from a workstation — the cloud images store no static keys.

—

Rendering the deployment…

Credentials. Secret Manager holds five values: Neo4j URI / username / password, the OpenAI query-embedding key, and the app scope-signing secret. Everything else Google-side is short-lived ADC metadata on the attached compute identity. NEO and the gateway must authorize that principal separately.

4 / Low level · Backend modules

FastAPI surface and the services behind it

Role-scoped routes in main.py, three routers, and a service layer. The workflow worker is the engine: it claims leased jobs from BigQuery and runs enrich → RCA or generation → RCA recheck.

—

Rendering the backend map…

Worker. Enabled by default, polling about every 15 s. Jobs are claimed under a lease (renewed while running) with idempotency keys on enqueue, so only one worker instance processes a job and retries stay safe. Agent calls are restricted to an allow-listed host.

5 / Low level · Sequence

Submission → automatic RCA

A submission enqueues an evidence job and an RCA job. The worker retrieves Neo4j passages, asks Sonnet to judge the answer, and saves an append-only diagnosis for the reviewer.

—

Rendering the submission sequence…

Failure posture. Gateway errors map to an explicit taxonomy (authentication, permission, rate limit, timeout, network, unavailable, request, response) and end the job as review-required with the saved answer retained — there is no automatic retry.

6 / Low level · Sequence

Reviewer retest → owner confirmation

A reviewer explicitly requests a fresh NEO answer against a chosen environment target. The worker generates it, rechecks it against evidence, auto-shares the safe result — and only the owner can resolve the report.

—

Rendering the retest sequence…

No Publish step. The reporter automatically sees the latest saved answer and safe RCA. Resolution needs the actual owner’s explicit confirmation for the latest completed result, on the current revision, in the same environment — a non-production result cannot resolve a production report.

7 / Low level · Data model

BigQuery tables in dataset agent_quality

One row of BigQuery is the system of record: feedback with an audit trail, leased workflow jobs, append-only answer and RCA versions, golden sets with evaluations, and the environment/promotion registry. Access grants live in the configured authz table and are cached server-side.

—

Rendering the data model…

Append-only history. feedback_events plus the *_versions tables are never overwritten; current values sit on feedback_items and history is rebuilt from versions. Access grants use the table named by FEEDBACK_AUTHZ_TABLE with a separate audit-history table.
